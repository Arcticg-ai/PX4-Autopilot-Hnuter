# 3131ddd4 实机大 Pitch 失稳分析（2026-08-07）

## 结论与飞行状态

该固件/参数组合不能作为大姿态可飞版本。两次 Position 模式实飞都在大 Pitch
阶段出现闭环失稳：Pitch 力矩长时间触及限制，尾部双向电机反复正反换向，一级倾转
左右通道共同摆动，最终触发 Pitch failure。`log_130` 随后 Kill，`log_131` 的失稳
持续约 30 s；后者所用尾电机在本次测试后损坏。

必须注意：飞行时 `HNTR_RC_ANG_MAX=45 deg`，所以手动 Position 模式内部 Pitch
目标并没有正常命令到 90 deg。日志里的 `72.3/74.2 deg` 是超过 45 deg 目标后的
失控过冲，不能当作 90 deg 跟踪能力。

风险级别：**禁止继续使用本提交和本参数组合进行带桨大姿态试飞**。尾电机/电调/
螺旋桨需完成硬件检查，修复版本也必须经过拆桨台架和系留小角度验证。

## 失稳机理

### 1. 控制器实际请求超过名义 Pitch 力矩上限

原代码先把 P/D/I 合成的 Pitch 力矩限制到 `+-HNTR_TAU_P`，转换成归一化力矩后，
再加 `HNTR_PITCH_BIAS`。在本次参数下，`10 Nm / (85.48 N * 0.664 m)` 约为
`0.176`，再加 `0.09` 偏置后，日志中的归一化 Pitch 力矩范围成为约
`-0.086..+0.266`。因此 `HNTR_TAU_P=10 Nm` 并不是最终总请求的严格上限，正负
方向能力也明显不对称。

对应源码：`src/modules/mc_rate_control/HnuterControl.cpp` 中原提交的
P/D/I 限幅和随后 `PITCH_BIAS` 叠加逻辑。

### 2. 尾部双向电机收到比实物换向更快的正反推命令

原分配器把正反推建模为完全对称的静态曲线，未表示正/反推力差、死区、转子惯量、
ESC 过零时间或换向等待。两个窗口内 `0.276/0.308 s` 的中位过零间隔已接近目测
约 `0.3 s` 的实物换向响应，控制器可能在上一方向的推力尚未消失时又要求反方向
推力。ULog 只有指令 PWM，没有尾电机 RPM/实际推力，所以这里是由指令频率和实物
观察共同支持的高概率机理，不是已经测得的传递函数。

### 3. 激进参数和执行器滞后共同降低相位裕度

`20/8/10`、Pitch 积分 `0.06` 与开环尾推映射组合，使误差增大时迅速进入力矩
限制；反向推力建立延迟后，误差继续增长，再触发相反方向的大命令，形成低频极限环
并最终发散。积分是加重因素，但不是唯一根因；仅关闭积分不能补上尾电机动态和换向
保护。

### 4. 一级倾转共同振荡是分配耦合，不像单舵机故障

`log_131` 中左右一级舵机命令相关系数约 `0.991`，共同角与 Pitch 约 `0.92`
相关、与 Body-X 推力约 `0.88` 相关。分配器根据尾推 `F3` 重新计算前部竖向推力，
又由 `atan2(Fx,Fz)` 计算一级倾转角；Pitch/尾推振荡因此会同步投影到两路一级舵机。
这解释了“大角度时一级倾转也一起振荡”，证据不支持把它归因于单侧舵机抖动或
`+-180 deg` 分支跳变。

原固件仍把舵机命令速率硬编码为 `50 rad/s`，显著高于舵机空载规格约
`4.7 rad/s`，也不能代表带载速度。ULog 没有实际舵角反馈，因此不能排除带载下垂、
齿隙、回差或未达到目标角度；但本次 Pitch 失稳的一级左右共同运动首先符合分配器
耦合路径。

### 5. allocator 的“已实现”标志不能证明实物实现了力矩

原 `ActuatorEffectivenessHnuter::getUnallocatedControl()` 强制把 6 维 residual
清零。因此日志里 `torque_setpoint_achieved=true` 只反映这个软件占位实现，不能
证明尾推、舵角或机体力矩真实达到目标，也不能给积分器提供有效的饱和反馈。

## 证据边界

ULog 能直接支持：固件身份、保存参数、姿态/角速度、飞控计算的力/力矩设定、执行器
命令 PWM、电池电压/电流、故障与 Kill 时序。ULog 不能直接支持：实际舵角、尾电机
RPM、实际正反推力、ESC 内部状态、绕组温度或烧毁的唯一原因。

因此本报告把“尾电机响应不够快、实际舵角未达到目标”列为需要台架测量的执行器
假设，而不是把命令值当反馈值。后续必须增加实际角度/RPM/电流/温度观测，或至少
完成受控台架阶跃和换向辨识。

## 后续验证门槛

1. 不使用本参数组合再次带桨测试。
2. 检查尾电机、双向电调和螺旋桨是否适合频繁正反推，完成绝缘、轴承、磁钢、绕组、
   电调温升和过零逻辑检查。
3. 修复固件先做拆桨输出检查：偏置最终限幅、尾推斜率、过零等待、舵机速率和
   DIS/FAIL 中点。
4. 带桨仅从系留 `+-10 deg` 开始，再到 `+-20/+-30 deg`；每一级都保存固件哈希、
   完整参数和 ULog，确认没有尾推快速反转、持续饱和或低频极限环后再扩大范围。
5. 在尾电机实际 RPM/推力、正反死区和延迟未辨识前，不进行接近 90 deg 的试飞。
